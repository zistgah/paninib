# PANINI genetic compiler v0.3

© 1993–2026 Abhishek Choudhary. All rights reserved.  ·  AyeAI

Canonical implementation: **Python**. The Pages workstation is a demonstrator.
The Rust tree is a contract sketch with stub modules so `lib.rs` resolves.

## Invariants

1. Intent ≠ Genetic CISC ≠ Microcode ≠ ATGC ≠ Physical execution
2. Desired Phenotype ≠ Predicted Phenotype ≠ Observed Phenotype
3. Compilation Success ≠ Execution Success ≠ Target Satisfaction ≠ Biological Validation

## What v0.3 fixed

- Genotype composition is a function of the program (`modules_for_intent`).
- `primary = head` and `primary = tail` emit different CISC, different loci,
  different twin trajectories, different predicted primary axes.
- Typed `PhenotypeConstraint` objects. `primary = tail` + `secondary = tail`
  infers `tail_count == 2`. The 1-D model still produces one axis. Target
  status is **UNSATISFIED**. That is the correct scientific result.
- Verification layers can fail. L10/V10 compare declared vs predicted.
  Verdict bundle separates compilation / simulation / runtime / target.
- Standard library is retrieved GRCm39 / MGI / NCBI annotation. No ATGC
  strings. Digests are over the retrieval record and are recomputed at
  build time (`verify_retrievals`).
- Loci use published coordinates (Fgf8 is chr19:45725237–45731354 −),
  not `10_000_000 + i * 40_000`.
- Every shipped locus drives a named field. `disable(Wnt3a)` zeros the
  Wnt field; `disable(Aldh1a2)` zeros RA.
- No millimetre figure. Axis extent is `uncalibrated`.
- Debugger `diff` reads the program's constraints, not a spec-document
  literal.
- Backends are a registry. `e_coli.k12` is a hard error. A `backend`
  clause in source is honoured.
- Published CISC vocabulary is the 16 defined opcodes. No State→State stubs.
- Organism filter is taxon-safe. `organism=mouse` does not return human.
- Realization package carries `authorization.authorized = false`, an
  empty assembly plan, and no designed constructs.
- Provenance DAG is derived from the passes that ran.

## What is still not this codebase

- A second independent posterior domain (two-tail *satisfaction*).
  The model can *represent* N axes; the 1-D backend initiates one.
- 2-D/3-D fields, meshes, GPU, SSA.
- Wet-lab execution. The authorisation object is the gate.
- Re-fetch from the live MGI/NCBI network on every build. Snapshots
  carry URL + digest; `verify_retrievals` recomputes the digest.

## Golden program

`examples/mouse_axial.panini` is the single source of the mouse axial
example. Do not fork a second copy with a different header.
